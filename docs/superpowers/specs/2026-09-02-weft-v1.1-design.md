# weft 设计文档 v1.1（引言/方法元数据 + 章节层级与生产粒度）

- 日期：2026-09-02
- 状态：v1.1 已实现（2026-09-02）；实现计划见 docs/superpowers/plans/2026-09-02-weft-v1.1-implementation.md
- 关系：增补 `2026-09-01-weft-design.md`（v1）。v1 §3 数据结构冻结条款继续有效——本文档是按该条款允许的方式做的**显式 schema 演进（v1.1）**，实现时需迁移脚本 + validate 全量回归。与 v1 冲突处以本文档为准。
- 内容来源：2026-09-02 设计讨论（引言拆解、method/param 分离、章节层级与生产粒度、uses 归属），样本为一段真实 MBGS-SNDPR 论文引言。

## 1. 背景与缺口

v1 的卡片与流水线围绕 Results & Discussion 打磨。三个缺口：

1. **引言**：原子内容 = 论断 + 引文，v1 的 claim(cited) + note 恰好覆盖，零新卡型（§2）。
2. **方法**：方法协议（可复用，跨文章相同）与实验参数（每篇不同）生命周期不同，v1 无处安放 → 新增 method/param 两卡型（§3）。
3. **章节层级与生产粒度**：v1 叙事层是扁平文件；需要"第一级章节路由工作流、part 为生产单位、段落为审阅单位"的层级结构（§4）。

## 2. 引言元数据（零 schema 改动）

- 引言的原子句 → **claim(cited) 卡**：statement + cites（1 个或多个 bib key）+ status，走与结果/讨论 claim 完全相同的审阅流与生成管线。id 与结果 claim **同池**（claim-NN 全局序号，不加前缀；本文档行文用 c-iNN 仅为简写）。
- 多引文共识句（"颗粒系统受限于启动期长 [hussain2024; lyu2025]"）= 一张卡 cites 多 key。
- **无引文常识句**（领域共识、自己的论证主张）：建 cited 卡、cites 留空 → 现有 `W-CLAIM-CITED-NO-CITES` 在审阅时提醒补文献。不新增字段、不建"共识卡"。
- **缝隙（gap）句**：也是 cited claim，引最近邻工作反衬（"Trebuch 快速建立了 MBGS-EBPR，但无曝气 MBGS-SNDPR 的快速启动未见报道" cites: [trebuch2023]）。背景/缝隙/假设等语义差别放叙事节点 logic 与 role（软词表 background/counterpoint/…），不进卡。
- **"本研究做了什么"段**：不建卡，归叙事层（node logic 承载行文指令）。其中结果预览句（"FISH-CLSM 与 qPCR 揭示两条光颗粒化路径"）直接 **use 结果章的 claim 卡**——一张卡穿引言与结果/讨论多个章节。
- 红利：此拆解即 §10「文章解析」场景的产品形态——从现成文献抽 cited claim 草稿卡 → 人审 → 引言/讨论共用。

## 3. 方法元数据：method 卡 + param 卡（新卡型）

### 3.1 method 卡：`metadata/methods/<slug>.md`

```yaml
id: qpcr                    # slug 命名（非 data-01 式编号），并入全局 id 唯一命名空间
derived_from: [tang2025]    # 可选：方法溯源，直接存 bib key（语义同 cites）
statement: "qPCR 定量功能微生物丰度（AOB/NOB/PAOs/DPAOs/GAOs/phototrophs）"
protocol: |                 # 无参数操作步骤，Markdown，库级复用载体
  1. 提取 DNA …
  2. 体系配置与扩增 …
status: approved
comment: ""
```

### 3.2 param 卡：`metadata/methods/params/<slug>.md`

```yaml
id: qpcr-main
method: qpcr                # 单向引用 method 卡，悬空 = 错误
values:                     # 本项目的具体参数，自由键值
  program: "95℃ 3 min；40 循环……"
  instrument: "QuantStudio 5"
derived_from: [trebuch2023] # 可选：参数方案借鉴
status: approved
comment: ""
```

目录 `methods/*.md` + `methods/params/*.md`，沿用 claims「目录名=属性」模式。

### 3.3 分离理由与边界

- 分离依据：① 一篇之内同一方法多次应用（qPCR 多靶点、多阶段反应器）；② 审阅粒度——协议是低风险抄写，**参数才是每篇需逐项核对的实验事实**；③ 库卡纯净：跨项目复用 = 整卡拷走即用，不被项目参数污染。
- 复用载体 v1.1 = **跨项目拷贝文件**。明确不做：方法库命令/全局库基础设施（YAGNI，第二次真实复用后再议）。
- AI 行文依据：method.protocol + param.values 一起进 prompt（graphgen 增加 param→method 反向边，复用 fact→data 链路模式）。

### 3.4 校验规则增补（v1 §4 的增量）

| 级别 | 规则 |
|---|---|
| 错误 | param.`method` 悬空引用；method/param id 重复（并入全局命名空间）；`derived_from` key 不在 .bib |
| 提醒 | `derived_from` key 在 .bib 但无 note 卡（同 note 卡规则）；method 无任何 param 引用（孤儿，并入 W-ORPHAN 检查范围） |

### 3.5 uses 目标类型扩展

叙事节点 `uses` 的目标从 fact/claim 扩展到 **param 卡与 method 卡**。悬空检查、graphgen 反向索引、spec_build 的实体 bundle（method→protocol+derived_from，param→values+method 概要）随之覆盖。

## 4. 章节层级与生产粒度

### 4.1 四粒度分工

| 粒度 | 职责 |
|---|---|
| chapter（第一级目录） | 路由生成工作流（§4.3） |
| 子节目录（3.1、3.1.1…） | 纯定位；标题层级映射给 Quarto，编号由 Quarto 负责（延续"内部标识/显示形式分离"原则） |
| part | **生产与组装单位**：一次 run、一个 qmd、一次重跑；语义完整段群（2-5 段） |
| node（段落） | **审阅单位**：status 逐段落定（不变） |

### 4.2 narrative 目录树（重构 v1 扁平文件）

```text
narrative/
├── 01-introduction/
│   ├── 01-background/part-01.md
│   └── 02-gap/part-01.md
├── 02-methods/
│   └── 01-bacterial-and-algae-cultivation/part-01.md
└── 03-results-and-discussion/
    └── 01-sndpr-performance/
        └── 01-startup/
            ├── part-01.md
            └── part-02.md
```

- **位置完全由目录路径 + 文件名前缀决定**；v1 的 `order` 字段**退役**（不留两套排序来源）。层级深度自由（chapter 下可直接放 part）。
- 目录名 = 序号前缀 + 人读文本（中文/空格可）；**命令一律用 id 寻址**（`weft draft part-startup-01`，loader 解析路径），目录名不影响操作。
- part 文件结构沿用 v1 narrative 文件（id / section / nodes；`section` = 本 part 渲染标题）；节点 id 全局唯一，迁移时保留原 id。
- 迁移：v1 扁平 narrative 文件每个退化为一个 part 文件（examples/paper-demo 仅 2 文件 4 节点）。

### 4.3 chapter → 生成工作流映射

| chapter | uses 主要目标 | 生成风格 | 温度 | 校验裁剪 |
|---|---|---|---|---|
| introduction | cited claim（+note 概括） | 综述串写，logic 权重大 | 中 | 引文闸门保留 |
| methods | param 卡（+method 协议） | 格式化展开，几乎不"创作" | 低 | 引文/claims 规则不适用；uses 越界与参数存在性保留 |
| results | fact/claim 实体卡 | 现有 draft_para | 中 | 不变 |
| discussion | 结果 claims + 引言 claims | 对比/解释/归因 | 中高 | 不变 |

工作流类型判定：part 文件可选 `workflow:` 字段；缺省按第一级目录名对已知词表（introduction/methods/results/discussion）前缀匹配；仍无匹配 → results 兜底。

### 4.4 生产与组装流水线

```text
weft draft <part-id>  →  drafts/<part-id>.md（段落级溯源注释，人逐段审）
weft assemble         →  generated/<chapter>/…/part-NN.qmd（已批准段落确定性拼装）
                         + 合并脚本按目录序拼 chapter 级 qmd（纯脚本无 LLM；heading 层级映射 chapter→#、子节→##/###）
weft render           →  quarto render（章节编号、crossref 由 Quarto 负责）
```

- **part 内段间前文传递**（翻 M2 决策 7 的案）：part 内 2-5 段，SpecModule inputs 别名把已生成段落注入后续段落任务；**跨 part 不传**，连贯性靠实体卡与 logic。
- 失败语义不变：任何硬规则违规 → 该 part 拒绝生成，不落盘；其余 part 不受影响（part = 失败隔离边界）。

## 5. uses 规范（v1.1）

- 格式不变：节点级结构化 `uses: [{id, role}]`；YAML block/flow 两种写法合法；role 软词表不变（超集放行仅提醒）。
- **归属：随节点走、随 part 文件走**。不建中央 uses 表（违反"关系单向存储、反向索引由脚本生成、不手写"）——"实体被哪些段落使用"由 `weft graph` 反向索引/orphan 报告回答。
- 不引入 part 级共享 uses 作用域：实体对多段有用就逐段列（重复诚实可审），纯背景进 logic。
- `logic` 内联 `[@id]` 提取糖：**缓议**（结构化写法经一篇真实写作验证痛点后再议；避免 M2 草稿侧"正文标记 vs 结构化数据"的复杂度重演）。
- 书写闭环（现有能力）：`weft review`/`weft graph` 查 id → 填 {id, role} → `weft validate` 的 E-DANGLING-REF 拦写错。

## 6. 实施边界（明确不做）

- 方法库命令 / 全局方法库基础设施。
- part 级共享 uses 作用域；中央 uses 表。
- logic 内联实体标记提取。
- 引言专用卡型或 gap 字段（语义由 logic/role 承载）。
